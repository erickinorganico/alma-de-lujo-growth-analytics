Its packet has exactly `version`, `cut_id`, `run_id`, `status`, `synthetic_business_data`, `current_cut_sha256`, `facts`, `unknowns`, `hypotheses`, `recommendations`, `challenges`, `analyses`, `review`, `provenance`, and `external_execution`. `start_cycle` is the current-cut authority. A cut without a prior register retains the existing required shape. A governed later cut may additionally contain exactly `decision_register` and `carried_decisions`. `decision_register` contains `version`, `register_id`, `prior_anchor`, and `anchor`; both anchors use the existing decision-register contract fields `version`, `register_id`, `terminal_hash`, `event_count`, and `origins_hash`. `scripts/validate_weekly_contract.ps1` accepts explicit schema path, definition name and instance path, constructs a temporary root schema whose `$ref` targets the named `$defs` member while retaining the complete `$defs` map, calls PowerShell `Test-Json`, emits only definition/status diagnostics, and exits nonzero on any invalid schema or instance. It never prints private instance content or writes a validation copy.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Producer → JSON Schema | Production artifacts are authoritative for current behavior, while the schema is the public integration contract; drift between them must fail CI. |
| Private artifact → validation process | Current cuts, packets and decision carry can contain private analysis; validation may inspect bytes but must not echo or copy them. |
| Schema fragment → PowerShell validator | A malformed definition name, unresolved `$ref` or invalid schema must fail rather than accidentally validate against the permissive document root. |
| Private terminal packet → public receipt | The public receipt may expose only synthetic task metadata, hashes, statuses and declared scope limits. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-19 | Spoofing | Named `$defs` selection | mitigate | Exact allowlist of definition names, fragment wrapper with the complete `$defs` map, and failure on absent/unresolved references. |
| T-03-20 | Tampering | Packet/current-cut contract | mitigate | Producer-derived positive fixtures, exact key parity, `additionalProperties: false`, required fields, constants, types and SHA-256 patterns. |
| T-03-21 | Repudiation | Contract drift result | mitigate | Deterministic test cases name the definition and mutation while preserving the nonzero validator result in CI logs. |
| T-03-22 | Information disclosure | Schema validator diagnostics | mitigate | Temporary synthetic inputs, status-only output, no JSON body/path echo and unchanged metadata-only acceptance receipt. |
| T-03-23 | Denial of service | Schema/instance validation | mitigate | Existing artifact size bounds, one definition per invocation and disposable bounded fixtures. |
| T-03-24 | Elevation of privilege | Packet authority fields | mitigate | `external_execution` remains the `PROHIBITED` constant; recommendation approval and execution constraints remain exact. |
| T-03-SC | Tampering | Package installation | mitigate | No package install; use the repository interpreter and built-in PowerShell `Test-Json`, with package manifests unchanged. |
</threat_model>
